# StageFlow Shared UX State & Component Language
**Status:** Draft v0.1
**Source fidelity:** Exact chat draft.

> **Repository interpretation:** This exact Draft v0.1 constrains future shared UX
> state and component behavior. It is not a frontend component library, design-token
> implementation, or acceptance of any unresolved domain authority decision.

## 1. Visual Character

Broadcast multiview discipline + modern operational software.

Dense but calm, stable, information-rich, low-animation, control-room appropriate, keyboard friendly, strong on external display and MacBook.

## 2. Healthy Is Quiet

Healthy state should not consume attention.

## 3. Three Operational Meanings

Never collapse Health, Impact, Attention.

## 4. Attention Classes

Producer:
- Information
- Review
- Intervention

Editorial:
- Priority
- Review
- Deferred

Related visual grammar, different workflow meaning.

## 5. Epistemic Labels

- OBSERVED
- DERIVED
- INFERRED
- DECLARED
- EXTERNAL

Use sparingly in defaults; available when provenance matters.

## 6. Proposal vs Authority

Proposals look different from authoritative facts.

## 7. Primary Status Phrases

Prefer operational language:
- No intervention required
- Package assembling
- Review required
- Media preserved
- Intelligence deferred
- Reconciliation required
- Editorial review in progress

Avoid generic `OK`, `Error`, `AI failed`.

## 8. Consequence-First Error Pattern

Communicate:
1. what happened
2. what is affected
3. what continues safely
4. whether user needs to act

## 9. Preservation Language

Use when ambiguity/revision implies risk:
- Media preserved
- Candidate retained
- Prior approval preserved
- Historical revision preserved

## 10. Stable Screen Geography

Critical live surfaces should not move major regions dynamically.

## 11. Dense Rows Over Card Grids

Prefer structured rows for Stage, Session, Queue, Candidate collections.

## 12. Primary Row Anatomy

Identity, contextual subtitle, primary state, secondary state, attention indicator, compact metrics, primary action/navigation.

## 13. Inspector Pattern

Rows remain scannable; inspectors hold evidence/provenance/history/actions.

## 14. State Chips

Use sparingly for bounded categories.

## 15. Color Semantics

Neutral normal, accent selection/live context, warning review/ambiguity, critical intervention, success explicit approval/completion. Color never sole carrier.

## 16. Animation

Minimal.

## 17. Time Formatting

Tabular numerals. Session-relative and wall-clock never mixed without labels.

## 18. Live Indicators

LIVE means currently live, not caught up or healthy.

## 19. Lag Component

Reusable consequence-oriented lag representation.

## 20. Work Counts

Counts must have precise semantics.

## 21. Attention Banner

Global banner only for meaningful conditions.

## 22. Empty Healthy State

Producer: No Producer work waiting.
Editorial: Caught up.

## 23. Stale Data State

Connection loss explicitly marks stale state and disables authority.

## 24. Recovering State

Recovering is distinct from available.

## 25. Disabled Action Explanation

Always say why unavailable.

## 26. Authoritative Action Pattern

State the fact being changed rather than generic confirmation.

## 27. Low-Risk Action Pattern

Navigation/playback/filtering stay fast.

## 28. Review Action Pattern

Editorial approve/reject/defer optimized for throughput, history preserved.

## 29. Automatic Decision Pattern

Auto decisions remain inspectable with policy/provenance.

## 30. Policy Withheld Pattern

Auto-approval withheld is not automation failure.

## 31. Timeline Marker System

Distinguish authoritative boundary, proposal, machine Candidate, Producer mark, Editorial approval, unresolved media.

## 32. Timeline Layers

Producer and Editorial share temporal grammar but emphasize different tracks.

## 33. Provenance Inspector

Operational meaning before raw object structure.

## 34. Revision Component

Package and Assembly revisions remain visibly separate.

## 35. Historical Indicator

Historical state clearly read-only.

## 36. External Context

Program Expectation is visually External; realized Session is Declared.

## 37. Search Pattern

Search remains contextual and preserves Session identity.

## 38. Filters

Filters represent user decisions, not implementation.

## 39. Pagination

Bounded collections truthfully communicate truncation.

## 40. Progressive Disclosure

Operational meaning → workflow detail → evidence/provenance → technical telemetry.

## 41. Worker Representation

Consequence first; node identity second; raw GPU/VRAM diagnostic only.

## 42. Offline/Event-Mode Language

Expected cloud deferral should not look like failure.

## 43. Keyboard Focus

Visible, discoverable, consistent; no accidental high-authority single-key actions.

## 44. Accessibility

Text+icon redundancy, color-independent meaning, contrast, visible focus, scalable type, meaningful labels.

## 45. MacBook and External Display

Larger displays add simultaneous context rather than simply enlarge; smaller displays collapse secondary panels first.

## 46. Responsive Priority

Preserve:
1. identity
2. attention
3. primary state
4. primary action
5. key consequence
6. secondary metrics
7. provenance/technical detail

## 47. Persona Identity

Producer operational/Stage-centric.
Editorial media/Session-temporal.
Shared typography, status language, provenance, controls, revision semantics.

## 48. Product Principle

StageFlow communicates:
- what is true
- how it knows
- what consequence exists
- who has authority
- what the human needs to do

before exposing implementation.
