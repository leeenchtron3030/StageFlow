# StageFlow Session Package Review UX Specification
**Status:** Draft v0.1
**Source fidelity:** Recovered accepted UX direction; not a verbatim reproduction.

> **Repository interpretation:** This is a recovered accepted-design summary from the
> handoff bundle, not a verbatim historical chat draft. It records product direction
> without claiming the described frontend or supporting capabilities are implemented.

## Purpose

Producer verifies that the Session is a complete and correct captured package.

This is **not** Editorial content review and not a full nonlinear editor.

## Header

Show:

- Session title
- participants
- optional organization/affiliation per participant
- Stage
- package state
- package revision

Panels/multiple participants are supported.

Metadata-only edits generally should not reopen a package unless policy explicitly says otherwise.

## Package lifecycle

Useful operational presentation:

- Assembling
- Review Required
- Ready for Review
- Complete
- Reopened

## Timeline

Show Session and modest before/after context.

Represent:

- included media
- media outside package
- unresolved/conflict
- gaps/overlaps
- authoritative boundaries
- proposed boundaries

For interval-less media use an explicit:

**UNPLACED / TIME UNKNOWN**

lane.

Never fabricate timeline placement.

## Continuity wording

Distinguish:

- `No gap detected`
from
- `Continuity proven`

based on evidence actually available.

## Boundary summary

Separate:

- authoritative declared boundary
- proposed derived/inferred boundary

Example labels:

- `PROPOSED · DERIVED`
- `PROPOSED · INFERRED`

## Media membership vs logical Session boundary

A media asset may overlap the Session boundary and remain a package member without destructive trim.

## Approval gate

Typical requirements:

- declared start,
- declared end,
- relevant media assigned,
- no unresolved items affecting package,
- no blocking conflicts,
- no known material continuity issue.

Optional descriptive metadata should not block approval.

## Approval confirmation

Producer explicitly confirms:

- boundaries,
- media completeness,
- no known material capture issue.

## Completed package

Show:

- revision
- approval actor/time
- duration/media
- Editorial Ready

## Post-approval change

Relevant late media or reassignment:

- creates new review revision,
- preserves prior approval historically.

Metadata-only correction generally does not create a package revision.

## Hot / Moment Candidates

Candidates may appear on the timeline as context but do not block package completion.

If a boundary correction would exclude a Candidate, notify the Producer and allow review/continue.
